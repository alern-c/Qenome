# MVP設計条件

[概要](overview.md) · [MVPタスク](mvp.md) · [開発手順](development.md)

## 入力と処理

入力はローカルSQLite DB、SELECT 1本、型付きバインド値、利用者指定CREATE INDEX。具体的な引数名・ファイル形式は未決。SELECTと候補DDLは別入力とし、元DBへ候補索引を適用しない。

元DB → 整合したsnapshot → baselineとvariantの隔離コピー → variantに索引追加 → 同じSELECTとバインドで計画・結果・時間・容量を比較 → レポート → closeと一時ファイル削除、の順に処理する。工程5までに、variantへの索引追加と計画・結果の比較までを実装した。時間・容量の比較とレポートは工程6以降（[開発と検証](development.md) の「工程5の索引適用と結果比較」）。

元DBを変更しないこととsnapshotの一貫性は別に検証する。WALを含む整合性を保ち、元DBへの書込・checkpointを避ける。外部writerを止められない場合の保証条件は未決。

## 結果と測定

結果一致は値の型、NULL、重複行数を保つ。順序指定の有無にかかわらず行の多重集合で比較し、並び順は参考として表示するだけにする（ORDER BYの正しさは確かめない）。実行のたびに値が変わる関数（`random` など）とスキーマ表を読むSELECTは比較しない。日付・時刻の関数、読む順で結果が変わりうる集約・ウィンドウ関数、LIMIT/OFFSET、ビュー・WITH句を含むSELECTは、一致なら一致、不一致なら比較不能とする。比較不能のときは、次に試すことを理由と対で示す。比較不能を一致や成功として報告しない。名前で見つけられない順序依存（GROUP BY対象外の列など）は不一致と出うる制限として扱う。詳細は [開発と検証](development.md) の「工程5の索引適用と結果比較」。

計測にはデータ、バインド、環境、SQLite版、ウォームアップ回数、測定回数・順序、時間の測定範囲、キャッシュ条件を記録する。代表値とばらつきを示す。回数、統計値、交互実行等の方式は未決。

容量は測定対象と時点を明示したDB全体の増分等を使う。厳密な索引単体サイズと混同しない。EQPの文言変更や計測ノイズを明示する。

## 失敗と保全

複数文、書込SQL、不正バインド、危険なDDLは拒否する。読取制限はSQL先頭の文字列だけに頼らない。重いクエリを中断できるようにし、正常・失敗・中断の全経路で接続と一時ファイルを片付ける。時間上限、終了コード、エラー形式、後片付け失敗の扱いは [開発と検証](development.md) の工程2・4・5に記録した。

## 実装前に決める事項

SQLiteの導入・配布方式と版、対応SELECTの範囲、バインド型と表現、許可するCREATE INDEXの範囲、SQL読取制限方式、snapshot作成方式、一時ファイル管理、測定設定、索引の書込負担の扱いは未決。入力契約と安全性に関わる未決事項を、推測で実装しない。
