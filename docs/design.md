# MVP設計条件

[概要](overview.md) · [MVPタスク](mvp.md) · [開発手順](development.md)

## 入力と処理

入力はローカルSQLite DB、SELECT 1本、型付きバインド値、利用者指定CREATE INDEX。具体的な引数名・ファイル形式は未決。SELECTと候補DDLは別入力とし、元DBへ候補索引を適用しない。

元DB → 整合したsnapshot → baselineとvariantの隔離コピー → variantに索引追加 → 同じSELECTとバインドで計画・結果・時間・容量を比較 → レポート → closeと一時ファイル削除、の順に処理する。これは実装予定の流れ。

元DBを変更しないこととsnapshotの一貫性は別に検証する。WALを含む整合性を保ち、元DBへの書込・checkpointを避ける。外部writerを止められない場合の保証条件は未決。

## 結果と測定

結果一致は値の型、NULL、重複行数を保つ。順序指定のないSELECTは行の多重集合で比較する。順序指定がある場合の厳密な対応範囲は未決。非決定的関数と不安定なLIMIT等は条件を限定する。比較不能を一致や成功として報告しない。

計測にはデータ、バインド、環境、SQLite版、ウォームアップ回数、測定回数・順序、時間の測定範囲、キャッシュ条件を記録する。代表値とばらつきを示す。回数、統計値、交互実行等の方式は未決。

容量は測定対象と時点を明示したDB全体の増分等を使う。厳密な索引単体サイズと混同しない。EQPの文言変更や計測ノイズを明示する。

## 失敗と保全

複数文、書込SQL、不正バインド、危険なDDLは拒否する。読取制限はSQL先頭の文字列だけに頼らない。重いクエリを中断できるようにし、正常・失敗・中断の全経路で接続と一時ファイルを片付ける。時間上限、終了コード、エラー形式、後片付け失敗の扱いは未決。

## 実装前に決める事項

SQLiteの導入・配布方式と版、対応SELECTの範囲、バインド型と表現、許可するCREATE INDEXの範囲、SQL読取制限方式、snapshot作成方式、一時ファイル管理、比較不能の分類、測定設定、索引の書込負担の扱いは未決。入力契約と安全性に関わる未決事項を、推測で実装しない。
